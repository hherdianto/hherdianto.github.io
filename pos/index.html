Ringkasan

Masalah & Solusi

Masalah
  • Kasir berjalan di tablet dengan koneksi internet yang tidak selalu stabil — sistem cloud murni akan menghentikan penjualan saat offline.
  • Sinkronisasi ulang pasca-offline berisiko transaksi ganda atau hilang.
  • Pemilik toko butuh visibilitas stok, pembelian, dan piutang (kas bon) secara real-time dari satu tempat.
Solusi
  • Satu monolit Laravel sebagai sumber kebenaran + PWA offline-first di tablet: transaksi di-commit ke IndexedDB dan struk tercetak sebelum request jaringan apa pun.
  • Sync engine dua arah yang idempotent — setiap batch membawa UUID v7 + Idempotency-Key sehingga replay selalu aman.
  • Backoffice Inertia untuk pemilik/admin: master data, pembelian, konsinyasi, piutang, laporan, dan audit log.

Sorotan Engineering

Keputusan Desain Kunci

  • Jualan tidak pernah menunggu jaringan. Transaksi di-commit lokal dan struk tercetak sebelum ada panggilan API; sync berjalan best-effort di belakang.
  • Idempotency menyeluruh. Header Idempotency-Key (UUID penjualan) membuat server aman menerima payload yang sama berkali-kali dan selalu mengembalikan respons asli.
  • Server adalah clock tunggal. Cursor versi monotonic di sisi server; crash di tengah pull aman diulang karena cursor hanya maju setelah delta berhasil ditulis.
  • Konflik eksplisit, tidak pernah menimpa diam-diam. Konflik data diselesaikan lewat kebijakan yang terdokumentasi, bukan overwrite otomatis.
